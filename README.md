## 数据刷新安全链路

`npm run refresh:data` 依次执行：

1. 限速、带超时/重试/缓存地读取公开来源；
2. 从公开 JS 数据字面量安全解析 staging 数据，不执行远端代码；
3. 标准化合同、x/SCU 单位、多奖励和蓝图；
4. 解析官方简体中文 `global.ini` 并生成派生词典；
5. 严格 JSON Schema 校验唯一的 LIVE 版本快照；
6. 来源交叉校验，保留全部冲突原值；
7. 拒绝 PTU/EPTU 输入，只更新 LIVE；同构建号的真实配方热修也可更新；
8. 检测交易数骤降、版本倒退、关键奖励缺失及已有汉化、图片、获取说明和中文描述退化；
9. 备份上一版稳定数据，再用 `.next` 原子替换；
10. 清理超过 14 天的备份。

任一步失败都不会覆盖稳定数据。语义指纹会忽略抓取时间、来源更新时间、数组顺序及二次来源的小版本噪声；合同、数量、奖励、图片、获取方式、汉化或 LIVE 版本没有实质变化时，脚本通常输出 `unchanged: true`，不改生成文件、不新增备份。唯一例外是页面版本快照与稳定交易/物品文档不一致：此时会先备份并只修复 `versioned-data.json`。发布前额外运行 `npm run refresh:data:publish-check`；来源为 `partial` / `failed` 或出现异常时会阻止发布。人工核验并注明日期的 Wiki 快照只作为背景与地点参考，不会伪装成实时结构化接口。

项目内 `.github/workflows/refresh-data.yml` 在每 6 小时的第 23 分钟检查 Dumper's Repo 维科洛 HTML 的精确 LIVE 版本、公开数据包的 HEAD 发布标识及 NAS 同步输入清单。2026-10-19 用户明确同意跟进同一 LIVE 的真实配方变化：构建号未变但数据包 URL/ETag（没有 ETag 时使用 Last-Modified）变化或尚未核验时，只下载一次主源数据包，安全解析并按稳定 ID 比较合同、需求/奖励数量与单位、蓝图/绑定、声望、类别和上下线状态。忽略时间戳、排序、空白、中文显示名和辅助来源状态；材料显示英文也不作身份键，避免官方 RCMBNT 代码与原 ASD 名称差异造成误报。

只有新的 LIVE、真实主源配方变化或待校准的汉化输入才进入原完整抓取；通过原防退化、内容审计、测试、Schema、构建后，保存 14 天备份并只提交实质候选。单纯网站 UI/数据包重打包、格式变化不会完整抓取辅助 API、构建、提交或部署。成功且无变化的主源核验只记在可丢弃 Actions cache，绑定精确 LIVE、发布标识、当前已应用配方指纹和脚本版本；不把抓取时间提交到 main。缓存丢失/损坏必须重核验，真实变化或失败不记为无变化；没有 HTTP 发布标识时保守逐轮下载主数据包比对，但仍不因格式噪声完整刷新。HEAD/GET 发布标识不一致、解析失败或来源不可达时报错并保留稳定数据，不使用陈旧 HTTP 缓存伪装成功。主源热修不能被汉化 no-op 缓存阻止。

既有 `.github/workflows/refresh-watchdog.yml` 每小时第 53 分钟只读取 GitHub 主任务运行记录：按最近成功完成时间判断，超过 8 小时未成功且无排队/运行中任务则补发一次正常轻量检查；最多每 30 天在非生产 `automation-heartbeat` 分支维护心跳。没有新增周审或并行刷新任务，正式部署仍只由 `main` 的真实变更触发 EdgeOne。GitHub schedule 可能延迟或丢轮，主任务与看门狗同受平台调度影响；小时级补偿缩短恢复窗口，但不能承诺严格每六小时必达。辅助 API/图库更新仍不独立触发完整刷新。

2026-10-20 增加缺图定向补齐（用户已明确授权检查通过后提交部署，发布实证见交接文档）：复用上述六小时主任务，无需新调度。完整 LIVE 刷新通过事实门禁后，或 LIVE/配方/汉化均无变化时，只查询最多 4 件缺图实体的 Wiki API；每件未成功的物品隔 24 小时再试，按最早检查时间轮转。新 ID/英文身份/精确 LIVE 重置该物品冷却；缓存丢失最多多查一次，不作为成功发布证明。蓝图不虚构封面，不扫描全站已有图片；失败或没有合格图片不修改生成数据、不构建/提交/部署。首次新增也使用这一受限批次，超过批次的缺图留待后续轮次，不承诺一次补完。

只接受与物品内部 class/UUID 精确对应且不超前于本站的 LIVE 记录，英文 slug 仅作查询别名，不作近似匹配或基础涂装替代。只下载 Wiki API 声明的公开 `media.starcitizen.tools` 资源，原图优先，失败时才尝试声明的缩略图，单物品最多 3 个 URL；拒绝跳转/占位/非图片、MIME 与文件签名不符、解码失败、过小/空白/全透明/极端长宽比及超出 12MiB/1600 万像素的文件。原字节按 SHA-256 命名保存，不裁切、不拉伸、不重压；新增 `sharp` 仅在 Node 刷新/测试中负责实际解码，不进入页面 JS。

已核实图、人工图、参考图和 AI 图在后续完整刷新中保持不变，只有人工修改既有映射才能替换。`data/source-snapshots/automatic-item-images.json` 离线保存准确 ID、来源/下载 URL、SHA、尺寸、源 LIVE 和水印状态（无法确认写 `unknown`）；`reviewItemIds` 只作候选发现，不能自动替换已有图片。冷却与待审候选只存可丢弃 `.cache/image-refresh/`，不提交时间戳到 main。真正补到新图时才同步 items/版本快照/metadata，备份自动图片映射并通过原审计、测试、Schema、构建与 main→EdgeOne 门禁。该分支不能改名称、数量、材料、奖励、汉化或 acquisition；不上 Google/Reddit 自动猜图，不在 CI 自动生成 AI 图片，不在公开页面新增来源或 AI 文字。

合同主图的离线映射现在必须显式列出对应 `itemIds`，禁止只因属于同一合同便把主奖励图片分配给附送护甲/弹药。人工确认的错误关联记入 `rejectedImages`，后续完整刷新和缺图重试均不能重新采用该物品对应的错误路径/来源。已有 `ai_redraw` 稳定关联优先于冲突的合同图或人工来源映射，自动刷新不能替换；需要重绘/替换必须另经人工准确性审核及用户确认。像素/格式检查无法证明著作权或画面身份绝对准确，不能把技术合格冒称全部授权或内容合格。

稳定数据位于 `src/data/generated/`；备份位于未提交的 `data/backups/`；HTTP 缓存位于未提交的 `.cache/`。

## 官方简体中文

最高优先级只读源：

`nas:/volume1/docker/starcitizen-shared-input/localization/data/localization/chinese_(simplified)/global.ini`

解析器处理 UTF-8 BOM、CRLF、注释、空行，并只在第一个 `=` 处分割键值。本机原刷新流程直接只读 NAS，读取失败中止，不回退文稿目录旧文件。GitHub 原刷新流程读取本仓库 `nas-localization` 输入分支：先锁定 commit，再从同一个 commit 读取 `source.json` 与 `global.ini.gz`，校验解压字节长度、SHA-256、版本标识；绝不执行输入分支代码。原始 INI 不进入 main 或 dist。派生快照仍只有 `data/localization/official-global-derived.json`，新增地点/商店官方键；`src/data/generated/localization.json` 保存最终词典及来源证据。

现有每 6 小时检查同时比较精确 LIVE 版本、已核验主源配方与 NAS 同步源哈希；新 LIVE、真实配方热修或待校准的汉化输入才进入原完整刷新，无新增定时任务、独立校准命令或 push 触发器。本机可继续用原 `npm run localization:derive` 导入 NAS 派生词典。INI 的 `Frontend_PU_Version`（含 Alpha 前缀）只能证明系列，不能声称确认精确 LIVE 构建；可信汉化源系列落后时允许已有精确键译名与英文回退，离线标记 pending。来源系列超前、PTU/EPTU、源不可达或字节校验失败仍保留稳定数据并报错。同一输入重复刷新不写数据；纯格式/排序变化且产品语义未变时不更新 main，现有工作流用可丢弃 Actions cache 记住成功审查的输入，避免重复完整刷新。缓存还绑定当前已应用数据的 metadata，切换汉化 A→B→A 时不能把历史 no-op 审查误当当前状态。没有材料性候选则跳过构建、提交和部署。缓存丢失最多多检查一次，不影响准确性。

生产来源限定为 NAS 当前有效的官方增强版或官方完全中文汉化版；不得恢复旧中英双语派生词典补词，读取失败保留当前稳定数据并报错。官方中文包也可能包含英文型号或增强注释，不能按是否含英文推断包种类，更不能按包名、日期、版本或固定 SHA 硬编码。源文件只能由所有者在 NAS 维护，本站无历史包选择或格式切换入口。

名称取首个非空行，支持 `,P` flags；中文单行、中文名称后附英文或规格均保留可靠主名。首行仅为英文型号时继续使用上游英文原名，绝不从第二行 `[发电 S1 军用 A]` 等规格寻找中文。明确拼接的英文尾缀可剥离，品牌、型号、等级不猜译。五件维科洛特殊载具继续按核验 key 匹配，不依赖英文后缀。地点按官方 key 的有效名称行匹配，IO 仍按同一核验对话 key 提取建筑名；新未知对话仍报错要求核对。中文包的真实译名调整可应用，英文身份、LIVE 数量和防退化门禁不变。

地点通过显式官方本地化键及已核对终端/地点 ID 的别名匹配，不能套用同名装备（例如 Frostbite 地点为“寒霜镇”，不是冷却器“冻伤”）。购买说明审计检查所有残留英文，不再只检查旧词黑名单。Green Circle、Sharp Shooters 尚无唯一官方对应，保留原文并仅在离线审计中警告；不得为了全中文猜译。中文括号英文、SCU、IO 建筑品牌、L1 等编号按规则保留。

中文优先级：官方 `global.ini` → 用户确认人工修订 → 已校准公民中文 → 英文原名。解析器会同时按内部标识、已核验键别名和官方英文原名精确匹配；合同标题使用显式核验过的官方键或唯一精确英文标题，不做模糊猜测。ASD 重组样本在官方文件中的正式名称本身就是 `RCMBNT-*` 代码，继续保留官方代码。官方派生快照预载全部物品、商品、TheCollector 合同与蓝图名称，使下一版 LIVE 新增条目可直接命中已提供的官方汉化。没有可靠中文时直接显示英文，禁止机器翻译和虚构名称；英文回退不阻塞有效 LIVE 发布。

## 图片政策

- 合同奖励图来自用户指定的 Star Citizen Wiki 公开页面，并记录原始 URL；
- 物品图与获取资料来自 Star Citizen Wiki 公共 API；
- SC Market 的公开游戏数据 API 用于版本和蓝图配方二次校验；玩家挂单价格不写入固定的维科洛兑换配方；
- UEX 的公开索引结果只作人工二次核对。其 robots.txt 明确禁止 GPTBot 且物品页受 Cloudflare 保护，因此刷新器不自动抓取、不绕过访问限制；
- Wiki 物品页没有图片时，可以使用 RSI Community Hub、公开论坛或玩家社区中能明确对应具体物品的实拍；此类图片必须在数据层标为 `community` 或 `base_model` 并保留帖子来源，公开页面不追加来源文字；
- 社区图片只用于补充展示，不参与合同字段、数量、版本或获取方式的事实判定；来源、是否带水印及临时替代关系只记在离线映射中，不在公开页面追加说明；
- `public/images/wikelo.webp` 是 Wiki 页面中的游戏内维科洛实景截图；
- 公开媒体服务器拒绝脚本访问时，只能通过普通浏览器页面加载后导入已经公开呈现的资源，不得绕过 WAF；
- 精确、清晰且比例合适的真实游戏图仍是第一选择。已有真实素材能确认具体物品，但因清晰度、构图、背景或画幅不适合网站时，允许使用 Image 2 基于原素材重绘成适合对应类别的站内图片；不得改变物品型号、配色、结构、涂装或关键辨识特征。此类图片只在离线数据层标为 `ai_redraw`，公开界面不再显示额外角标，也不能在维护数据中冒充精确原始截图。
- AI 重绘必须保留参考页面、参考图片 URL、成图 SHA-256、生成产物标识、水印状态和重绘说明。没有能确认物品身份的真实参考素材时继续显示统一占位，不得仅凭名称凭空生成；AI 图片只补充视觉展示，不能用于证明配方、数量、版本、掉落地点或物品属性。
